How live data reaches this page

Your browser requests launch data directly from Launch Library 2. It asks for the next {{ listLimit }} scheduled launches and the {{ listLimit }} most recent ones, and keeps a copy for {{ listTtl }} minutes so that the free request limit lasts. Mission pages request the full record and keep it for {{ detailTtl }} minutes. Search and filters run on that saved copy. If a refresh fails or the limit is reached, MissionWatch shows the saved copy and labels it, rather than showing nothing.

Historical statistics come from a snapshot of GCAT that is built when the site is deployed, so the Analytics page never depends on a rate-limited service.

Measured, derived and estimated

Measured

Values reported by a source, such as scheduled times, statuses, outcomes, mission timelines and launch updates. Each record keeps its source identifier.

Derived

Values MissionWatch calculates from measured data, such as launch counts, success shares and the "featured" selection on the dashboard.

Estimated or approximate

Dates that the source gives only to the day, month or quarter are shown at that precision, without a countdown. Keyword-matched imagery and any future model output are always labelled.

How source data is interpreted

  • Launch Library 2 statuses map to MissionWatch statuses one to one. "Payload Deployed" stays a separate status and is not counted as a success until the source records an outcome.
  • GCAT launch categories O (orbital) and D (deep space) count as orbital launch attempts. Pad explosions and pad aborts are excluded because no launch took place.
  • GCAT's fractional success codes (for example OS80 or OF40) are shown as partial failures. A few subsidiary agency codes are merged: Chinese CASC institutes into CASC, and both ULA codes into ULA.
  • Launch Library 2 and GCAT name providers differently, so dashboard statistics (GCAT) and launch lists (Launch Library 2) are not joined record by record.
  • Schedule-change history needs snapshots recorded over time. That starts with the backend data pipeline (Phase 5). Until then, mission pages show the sourced launch updates instead.

Models and predictions

No predictive model is deployed. Delay-risk estimates (FR-11) will only appear after a model has been trained on stored schedule snapshots, evaluated on chronologically later data and compared with a simple baseline. Each prediction will show the model version, the training period and the evaluation results. If the data turns out to be insufficient, MissionWatch will publish historical analytics only.

Explanations such as SHAP describe how the model behaves. They do not establish real-world causes of a postponement.
